# Patterson VitePress site

A Patterson Companies branded [VitePress](https://vitepress.dev) documentation site.
VitePress `^2.0.0-alpha.19`, install-verified, with a committed lockfile.

## Scaffold

```sh
bun create patterson-vitepress my-docs
cd my-docs
bun run docs:dev
```

`bun create` copies this directory into the target, runs `bun install`, and initializes
a git repository there. Three caveats, verified against Bun 1.3:

- **Point it at a new directory.** `bun create` does not refuse an existing one — it
  replaces the contents, without a prompt. A file already sitting in the target is
  gone afterward.
- **The `name` field is rewritten** to the target directory name, so the scaffolded
  project is `my-docs`, not `patterson-vitepress-site`. Everything else is copied
  verbatim, `.gitignore` included.
- **The template is resolved from `~/.bun-create/patterson-vitepress`.** If that copy
  is missing, `bun create` falls back to looking the name up on npm, where it does not
  exist. Register it once with
  `cp -R <plugin>/ds/templates/vitepress ~/.bun-create/patterson-vitepress`.

If you would rather not register anything, copy the folder directly:

```sh
cp -R "${CLAUDE_PLUGIN_ROOT}/ds/templates/vitepress" my-docs
cd my-docs
bun install
bun run docs:dev
```

## Scripts

| Script | What it does |
|---|---|
| `bun run docs:dev` | Dev server on `http://localhost:5173` |
| `bun run docs:build` | Static build to `docs/.vitepress/dist/` |
| `bun run docs:preview` | Serves the built site locally |

There is deliberately no `start` script. `bun create` executes a template's `start`
script when one exists, and a dev server that never exits would hang the scaffold.

## Layout

`docs/` is the VitePress source root, which is why every script passes it. Config and
theme live under `docs/.vitepress/`, and `docs/public/` is served from the site root.

## Customization points

| What | Where |
|---|---|
| Site title and description | `docs/.vitepress/config.ts` |
| Sub-path deploys | `docs/.vitepress/config.ts`, the commented `base` field |
| Top nav and sidebar | `docs/.vitepress/config.ts` — the sidebar is not autogenerated |
| Footer, appearance toggle, last-updated label | `docs/.vitepress/config.ts`, `themeConfig` |
| Brand theme | `docs/.vitepress/theme/custom.css`, the only brand file |
| Vue components | `docs/.vitepress/theme/index.ts`, via `enhanceApp` |
| Logos and favicon | `docs/public/` |
| Hero and feature cards | `docs/index.md` frontmatter |
| Pages | `docs/`, mirrored by URL path |

## The accent and contrast policy

Sky `#00A8E1` is the brand's signature color and the easiest one to misuse. White text
on sky fails WCAG contrast, and so does sky text on white.

- On a **light** canvas, navy `#003767` carries strong text and link blue `#147EC2`
  carries links. Sky appears only as non-text chrome, such as the nav hairline and the
  focus ring.
- On a **dark** canvas, sky and light blue `#6DCFF6` carry the accent, text included.

That split is why `--vp-c-brand-1`, which VitePress uses for link text, differs from
`--vp-c-brand-3`, which is the solid fill behind reversed text. Primary button hover on
light is a lighter navy `#315D83`, never sky. Everything is sentence case, with no
uppercase transforms, and there is no emoji anywhere.

The shape language is 5px. The Patterson docs UI kit ships a 9px radius as a kit
convention; the brand value is 5px, and this template uses the brand value.

## The font policy

Proxima Nova is served by Adobe Fonts kit `uth1qfm`, linked from the `head` entry in
`docs/.vitepress/config.ts`. Adobe's terms do not permit re-hosting Typekit payloads, so
this template ships no font binaries and no `@font-face` declarations. Arial is the
sanctioned substitute when the kit is unreachable.

## Dependencies

`vitepress@^2.0.0-alpha.19` is the only one. Adding a dependency to this template means
supply-chain scoring it first.

Two things follow from that version being a caret range on a pre-release. A fresh
`bun install` resolves the newest matching 2.x rather than the exact build this template
was verified against, so **`bun.lock` is what reproduces the verified site** — keep it
committed and install from it. And a 2.x alpha can still land breaking changes between
releases; pin the exact version if you need the theme to hold still.

## Two build-time behaviors to know

- **Dead links fail the build.** If you delete a page, delete every link to it, or set
  `ignoreDeadLinks` in `config.ts`.
- **`lastUpdated` reads git.** Outside a git repository it simply renders nothing; the
  build still succeeds.
