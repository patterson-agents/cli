# Design system reference

## Choosing a starter

| Need | Use |
|---|---|
| Docs on Vite with a lighter toolchain | **This starter**, `patterson-vitepress` |
| Docs, guides, and reference on Astro | `patterson-starlight` |
| Interactive, in-browser coding tutorial | `patterson-tutorialkit` |
| Static docs UI kit with no build step | `patterson-docs` |
| Single on-brand marketing page | `patterson-corporate-page` |

`patterson-vitepress` and `patterson-starlight` cover the same job from different
toolchains. Pick VitePress when the team already writes Vue or wants a single Vite
dependency; pick Starlight when the site needs Astro's content collections, MDX
components, or a wider integration ecosystem.

## Project layout

```text
package.json                        vitepress ^2.0.0-alpha.19
bun.lock                            committed, install-verified
docs/
├── .vitepress/
│   ├── config.ts                   title, nav, sidebar, head, footer, appearance
│   └── theme/
│       ├── index.ts                extends the default theme
│       └── custom.css              THE brand file — every --vp-* override
├── public/                         favicon and logo lockups, served from /
├── index.md                        home layout: hero + features
├── getting-started.md
├── guides/                         task-shaped how-tos
└── reference/                      lookup-shaped reference
```

The `docs/` subdirectory is the VitePress source root, which is why every script passes
it: `vitepress dev docs`, `vitepress build docs`, `vitepress preview docs`. The build
output lands in `docs/.vitepress/dist/`.

## Configuration reference

| Field | Where | Notes |
|---|---|---|
| `title`, `description` | `config.ts` | Also feed the document title and meta tags |
| `base` | `config.ts` | Only for sub-path deploys. Commented out by default |
| `lastUpdated` | `config.ts` | Reads git commit times. Shows nothing outside a git repo |
| `appearance` | `config.ts` | Light and dark toggle. Both themes are tuned |
| `cleanUrls` | `config.ts` | Drops `.html` from URLs |
| `head` | `config.ts` | Carries the Adobe Fonts kit link and the favicon |
| `themeConfig.nav` | `config.ts` | Top bar. Sentence case |
| `themeConfig.sidebar` | `config.ts` | Not autogenerated — a new page needs an entry |
| `themeConfig.search` | `config.ts` | Local provider, no external service |
| `themeConfig.outline` | `config.ts` | Levels 2 and 3, matching the Starlight starter |

## Dependencies

| Package | Range | Notes |
|---|---|---|
| `vitepress` | `^2.0.0-alpha.19` | Supply-chain scored: supply chain 97, maintenance 95, vulnerabilities 100, license 100, quality 86 |

The only dependency. Adding one to this template means scoring it first and surfacing
anything below 90 — as `quality` is here, at 86. That dimension reflects repository
signals on a build-time tool rather than anything reachable in a published site, and it
carries none of the weight a low supply-chain or vulnerability score would.

The range is a caret on a pre-release, so `bun install` resolves the newest matching
2.x, not the exact build this template was verified against. `bun.lock` is what
reproduces the verified site; pin the exact version if the theme needs to hold still.
